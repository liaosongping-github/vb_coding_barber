# 邻剪生产系统上线总计划

> **供 Agent 执行：** 本文是跨阶段总计划与唯一进度入口。执行具体研发任务前，必须先为当前阶段编写包含精确文件、测试和提交点的阶段实施计划；实现阶段推荐使用 `superpowers:subagent-driven-development`，单 Agent 连续执行时使用 `superpowers:executing-plans`。所有步骤使用复选框维护状态。

**目标：** 以冻结的 v0.2 试运行 MVP 为产品基线，完成真实微信端、生产服务端、持久化数据、通知、运维和发布能力，并把通过验收的精确版本部署到生产环境。

**推进方式：** 按“产品基线确认 → 技术选型 → 架构契约 → 生产工程 → 业务闭环 → 系统验收 → 生产发布 → 试运行复盘”推进。每一阶段都有人工决策门、自动验证证据、独立中文提交和可恢复的交接记录；后续 Agent 只能从最近一个已通过的门禁继续，不得跳过未决策事项自行假设。

**当前产品基线：** `workspace/product/v0.2/`。该目录是冻结的 Web 高保真交互原型，只用于说明产品范围、页面目标和业务交互，不作为生产代码复用，不部署上线，也不纳入生产发布门禁。

**当前候选技术栈：** 尚未决策。技术选型必须由 Task 2 形成并接受 ADR 后才能初始化 `workspace/engineering/platform/`；本文不会用原型中的 Vinext、Cloudflare Worker、D1 或 Sites 配置推断生产架构。

**产品规格：** `workspace/product/v0.2/PRD.md`、`workspace/product/v0.2/acceptance-criteria.md`、`knowledge/business/business-rules.md`、`knowledge/business/service-flow.md`、`knowledge/business/权限与通知.md`。

## 全局约束

- `workspace/product/v0.1/` 与 `workspace/product/v0.2/` 均为冻结交付物，不得修改。
- v0.2 原型不部署；生产发布门禁不得调用原型部署或以原型托管结果代替生产验收。
- 任何新增或改变的业务规则必须先创建新产品版本，并同步 PRD、验收标准和测试用例。
- 技术栈、仓库结构、数据库、身份、通知和部署拓扑必须先由 accepted ADR 确认，随后才能生成生产工程。
- 队列写操作必须由服务端原子处理，并明确幂等、并发冲突、事务边界与重试行为。
- 顾客最多持有 3 个有效号码；每位理发师一次只能服务一个号码；当日号码不能跨日保留。
- v0.2 不包含地图、距离、导航、收藏、用户个人页、支付、评价或未来日期预约。
- 所有提交说明使用中文，并按可独立回滚且已完成验证的最小完整单元提交；不得混入无关改动。
- 不提交密钥、依赖、缓存、构建产物、本地日志或临时文件。
- 不手工修改 `knowledge/engineering/generated/`；代码变化后运行 `pnpm knowledge:generate`。

## 完成定义

只有同时满足以下条件，才能把本计划标记为完成：

1. 用户端、理发师端和管理端真实运行在目标微信环境中，服务端和数据库运行在生产环境。
2. v0.2 验收标准对应的生产端到端用例全部通过，且队列并发、幂等、跨日清理和权限边界通过专项测试。
3. 真实微信登录、手机号绑定、管理员预录理发师绑定和订阅消息完成联调。
4. 数据备份恢复、监控告警、审计日志、限流、安全检查和故障回滚完成演练并有证据。
5. 生产域名、证书、隐私政策、用户协议、微信平台配置和必要主体资质通过核验。
6. 发布精确提交已打标签并部署；健康检查与三端冒烟测试通过。
7. `knowledge/releases/` 已记录部署提交、标签、生产地址、发布时间和验证结果，工作树干净。

## Agent 接手协议

任何新 Agent 或其他工具接手时，必须按以下顺序执行；不得只依赖上一段对话：

1. 阅读根 `AGENTS.md`、`README.md`、`knowledge/README.md` 和最新发布记录。
2. 阅读本文的“当前进展快照”“当前执行点”和目标 Task。
3. 阅读目标目录的 `AGENTS.md`、`README.md`，以及目标 Task 列出的输入文件。
4. 执行只读基线检查：

   ```powershell
   git status --short --branch
   git log -5 --oneline --decorate
   git diff --check
   ```

5. 若工作树有未提交改动，先识别其所有者和目的；不得覆盖、回退或混入当前提交。
6. 只认领一个最小完整 Task 或阶段计划中的一个独立任务；开始前把“当前执行点”更新为该任务。
7. 完成后运行该任务规定的测试，记录命令、结果、提交和风险，再更新本文。
8. 所有提交使用中文；提交前再次核对 `git status` 和实际差异。
