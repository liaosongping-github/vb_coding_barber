# 邻剪平台 v0.2 试运行 MVP PRD

## 产品定位

面向已有摊位位置认知的熟客，提供“查看营业和排队状态—当天线上取号—动态查看进度—现场服务”的试运行 MVP。当前试运行有 2 名理发师，目标是验证营业状态、实时排队、线上取号和队列推进闭环。

## 用户端

- 微信授权、手机号绑定和订阅消息授权。
- 底部导航只有首页和我的排队；不提供收藏页或用户个人页入口。
- 首页以理发师列表展示营业状态、价格、排队人数和预计等待时间；不展示地图、定位、导航、距离、距离排序或附近发现概念。
- 所有营业中理发师卡片提供“立即取号”，歇业状态不可取号。
- 理发师详情展示环境、文字营业地址、营业时间、价格、平均时长和实时队列。
- 一次选择 1–3 人取连续号码；总有效号码最多 3 个。
- “我的排队”按进行中、已过号、已完成切换，并按理发师分卡展示；保留取消号码和联系信息，不提供地图导航。
- 取号成功后自动进入我的排队。

## 理发师端

- 首次通过管理员预录手机号绑定身份。
- 工作台展示营业状态、今日完成数、本次文字地址、当前服务、下一候选、队列和过号列表。
- 开店从历史文字地址中选择或新增文字地址；不使用地图定位、不保存距离。
- 当前服务可完成，下一候选可开始服务或过号；过号顾客可确认顺延。
- 非空队列强制关店需二次确认，服务中号码必须先完成。
- 数据页展示每日营业额估算、完成服务、过号和取消数量。
- 我的页展示绑定手机号、修改入口、营业地址、常规营业时间、平均单客时长和消息帮助。

## 管理端

- 管理员微信登录和权限校验。
- 概览营业理发师、实时排队及今日取号、完成、取消和过号。
- 管理理发师入驻、绑定状态、账号启停、文字地址和历史记录。
- 查询用户当前号码和完成、取消、过号记录。
- 只查看队列和记录，不直接修改实时队列。

## 关键规则

队列规则以 [`knowledge/business/business-rules.md`](../../../knowledge/business/business-rules.md) 为权威来源，状态机以 [`service-flow.md`](../../../knowledge/business/service-flow.md) 为准。v0.2 不改变同一或不同理发师合计最多 3 个有效号码、一次为 1 至 3 人生成连续号码、取消/完成/过号/顺延后的队列重算，以及理发师和管理端核心流程。

## 非功能与原型边界

v0.2 是响应式 Web 高保真试运行原型，用内存状态演示关键交互。微信能力、订阅消息、数据库和服务端原子性仅作为产品规则呈现，不是真实集成。地图服务不进入本版本技术选型；服务地址仅以文字保留，开店不依赖地图定位。
